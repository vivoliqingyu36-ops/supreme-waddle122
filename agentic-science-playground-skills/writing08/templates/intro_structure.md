# 引言与相关工作 · 逐节模板（intro_structure）

> 用法：写作时把 `{…}` 占位符替换为真实内容；**每个含事实/判断的句子后写 `[claim: cNN]`**，
> `cNN` 与 `source_map.json` 中的 claim_id 一一对应。删除占位符里写不出的内容，不要硬填。
> 数字编号引用（[1]）与作者-年份引用（Smith 2023）二选一，按目标期刊；混用是硬错误。

---

## 0. 落笔前必填的「事实卡速查」（对应 SKILL.md 步骤 3）

每篇候选文献一张卡，字段只来自该文献原文：

```text
work_key: {w1}
作者/年份: {…}
出处/DOI: {来源照抄，没有写 null}
问题设定(problem_setting): {…}
方法路线(method_route): {…}
数据与评价(data_eval): {…}
作者宣称的结论(stated_conclusion): {…}
适用条件(applicability): {…}
局限(limitation): {来源没写就写「未报告」}
证据定位(evidence_loc): {文件+行号/页码}
```

## 1. 研究背景（立得住）

写法：**具体脉络 → 具体未解决问题 → 为什么现在卡住**。点名 ≥2 个里程碑工作，禁止「近年来受到广泛关注」。

```markdown
{领域/任务}的研究可分为两个阶段：{里程碑工作 w1 [claim:c01]} 首先{用 X 路线解决了 Y [1]}；
随后 {w2 [claim:c02]} 把{设定扩展到 Z}，使{某指标/能力}达到{具体值或水平 [2]}。
然而，现有方法在{具体场景}上仍面临一个未解决的问题：{技术约束/数据限制/评价缺口 [claim:c03]}。
{一句话说明该约束为何此前无法绕开、为何现在具备解决条件（新数据/新工具/新算法）[claim:c04]}。
因此，本文聚焦{本文问题 P}。
```

检查（对 checklist）：每句有 claim；有 ≥2 个带引用的具体工作；有具体未解决问题；有「为什么现在」的理由。

## 2. 相关工作（分得清）

写法：按 `problem_setting` 或 `method_route` 分组，每组一段；段首一句点出该组研究的问题，随后用**同维度差异句**比较。不写逐篇摘要。

```markdown
## 相关工作

### 2.1 {组名：某问题设定 / 某技术路线}

围绕{该组要解决的问题}，主要存在{路线 A}与{路线 B}两条路线。
{路线 A}的代表 {w3 [claim:c10]} 采用{方法}，在{数据}上报告{结论}，但其适用限于{条件}、局限是{局限 [3]}。
{路线 B}的 {w4 [claim:c11]} 与 {w3} 同设{问题}，但改用{不同方法}，以{代价/牺牲}换取{收益 [4]}。
相较之下，{w5 [claim:c12]} 覆盖了{更多/更少的评价维度}，但{其局限}。
综合来看，这一组工作的共同限制是{限制}，未覆盖{具体场景}。

### 2.2 {另一组}

{同上结构，仅比较本组内的工作，不跨组重复比较。}
```

检查：每组有「组内差异句」；每处转述只来自该文献的结论/适用/局限；来源没写的局限写「未报告」。

## 3. 研究空白（说得实）

写法：**空白只从已引文献的缺口推出**，按四类之一写，并立即写本文如何填补。

```markdown
从上述工作可以看出，现有方法存在三处空白，本文分别对应：

1. **共同限制**：{w3 [claim:c20]} 与 {w5 [claim:c21]} 都依赖{强假设/大量标注/特定数据}，
   在{目标场景}下这一限制尚未被解除 [3][5]。本文以{本文方法 P 的做法}直接去掉该假设（见 §{方法}）。
2. **未覆盖场景**：现有工作只在{已覆盖场景}上评测，{具体场景 [claim:c22]} 未被任何已引工作覆盖 [4]。
   本文在 §{实验} 增加该场景的评测。
3. **冲突结论**（若存在）：{w4} 报告{结论 A}，而 {w6} 报告{结论 B}，二者在同一指标上不一致 [4][6]；
   本文在 §{实验} 复现并给出一个可解释的分歧来源。

（若以上三类都凑不出依据：）
**候选空白（作者判断，不由已引文献推出）**：{写或省略}。此条不挂引用，标注 [作者判断]。
```

检查：每条空白有 gap_type；前两类/冲突类有依据文献键；本文填补来自本文事实，不借用他人做法。

## 4. 贡献（对得上）

写法：编号列表；每条一个可核对动作，末尾标证据定位；没有证据的贡献降级为「计划/假设」。

```markdown
本文的贡献如下：

1. 我们提出{方法名}，{一句话说清它做了什么}（§{方法}，公式 ({n})，图 {n}）。
2. 我们在{数据集/基准}上验证{方法}，{关键数字/结论}（表 {n}，图 {n}，§{实验}）。
3. 我们给出{某个可复用组件/理论保证/开源资源}（§{位置}）。
```

每条贡献 → 证据对照（写入 `source_map.json` 的 `contributions`）：

| 贡献 | 本文证据 | 证据状态 |
|---|---|---|
| g1 | §{方法}、公式({n})、图{n} | verified |
| g2 | 表{n}、图{n}、§{实验} | verified |
| g3 | §{位置} | verified/missing |

## 6. claim → 证据表（写完全文后回填，写入 source_map.json）

| claim_id | claim_text | claim_type | source（引用键 / 文件定位 / 作者判断） | status | quote_or_paraphrase | needs_human |
|---|---|---|---|---|---|---|
| c01 | {…} | background_lineage | citation_key: w1 | cited | {原文句/紧贴转述} | false |
| c03 | {…} | background_problem | evidence_loc: paper_facts.md#L2 | cited | {原文句} | false |
| c22 | {…} | gap_premise | citation_key: w4 | cited | {原文句} | false |
| c40 | {…} | contribution | evidence_loc: paper_facts.md#L9 | cited | {原文句} | false |

claim_type 枚举：`background_lineage`、`background_problem`、`prior_work_claim`、`gap_premise`、`gap_statement`、`contribution`、`fill_relation`、`fact`。完整约束见 `schema/writing_schema.json`。
